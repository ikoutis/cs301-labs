The softmax, translated

def softmax_rows(S):
    shifted = S - S.max(axis=1, keepdims=True)
    E = np.exp(shifted)
    return E / E.sum(axis=1, keepdims=True)

def softmax_rows_torch(S):
    shifted = S - S.max(dim=1, keepdim=True).values
    E = torch.exp(shifted)
    return E / E.sum(dim=1, keepdim=True)
  • An AI assistant translated the NumPy function to stated requirements: a tensor in, a tensor out, no loop, no NumPy, and not PyTorch's own softmax.
  • Three differences: torch.exp for np.exp; dim and keepdim for axis and keepdims; and .values after S.max(dim=1, keepdim=True), which returns the largest values together with their positions.
  • No NumPy inside: NumPy cannot compute with a tensor that is on a GPU.

A second processor: the GPU

  • The processor that has run every program of this course so far is the CPU, the central processing unit: a few cores, each able to run any program, one instruction after another, very fast.
  • A GPU, a graphics processing unit, was built for one kind of work: the colours of the pixels of a screen, many times a second. One short computation, repeated for millions of pixels that do not depend on each other. So: thousands of small cores that carry out the same instructions on different numbers at once, and a memory of its own. The T4 that Colab lends has 2,560 cores and 16 GB.
  • A product of matrices is work of the same kind: each entry of the result is a sum of products that depends on no other entry. That is why neural networks are computed on GPUs.

The page CPU and GPU, parts 1 and 2, shows the two processors side by side: ikoutis.github.io/cs301-labs/unit-2/pages/cpu-and-gpu.html

A tensor lives on a device

if GPU:
    X_g = X_t.to("cuda")                 # copies of the three tensors, in the memory of the GPU
    W_g = W_t.to("cuda")
    b_g = b_t.to("cuda")
    print("X_g is on the device:", X_g.device)

    try:
        X_g @ W_t.T                      # X_g is on the GPU and W_t is on the CPU
    except RuntimeError as error:
        print("X_g @ W_t.T fails:", error)

    S_g = X_g @ W_g.T + b_g              # the line of Act 1, carried out by the GPU
    print("S_g is on the device:", S_g.device)
  • X_t.to("cuda") copies the numbers of a tensor into the memory of the GPU and returns the copy. PyTorch names the GPU cuda, after the system with which NVIDIA's GPUs are programmed.
  • An operation needs all of its tensors on one device, and that device's processor carries it out: X_g @ W_t.T fails. .cpu() copies a result back. The line of the scores does not change.

Measure the product on both processors

def time_product(size, device):
    """The average time, in seconds, of X @ W.T + b on the device, with n = m = K = size."""
    X = torch.rand(size, size, device=device)        # random float32 numbers, made on the device
    W = torch.rand(size, size, device=device)
    b = torch.rand(size, device=device)
    repeats = max(1, min(200, 8_000_000_000 // size ** 3))     # many repeats when the product is small
    finish(device)
    start = time.perf_counter()
    for _ in range(repeats):
        S = X @ W.T + b
    finish(device)
    return (time.perf_counter() - start) / repeats
  • n, m and K all equal to size, random numbers made on the device, many repeats when the product is small.
  • Two details particular to a GPU: PyTorch hands the work to the GPU and goes on at once, so finish waits with torch.cuda.synchronize() before the clock is read; and the first use of a device is slow, so one small product is run first and not measured.

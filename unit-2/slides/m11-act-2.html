The softmax, translated

def softmax_rows(S):
    shifted = S - S.max(axis=1, keepdims=True)
    E = np.exp(shifted)
    return E / E.sum(axis=1, keepdims=True)

def softmax_rows_torch(S):
    shifted = S - S.max(dim=1, keepdim=True).values
    E = torch.exp(shifted)
    return E / E.sum(dim=1, keepdim=True)
  • Translated by an AI assistant to stated requirements: a tensor in, a tensor out, no loop, no NumPy
  • Three differences: torch.exp; dim and keepdim; .values
  • No NumPy inside: NumPy cannot compute with a tensor on a GPU
Notes. The NumPy function of Act 1 beside its translation. Three differences: torch.exp for np.exp; dim and keepdim for axis and keepdims; and .values after S.max(dim=1, keepdim=True), which returns the largest values together with their positions. The full notebook has each group translate its own function after class, and Review Quiz 11 asks for the list of differences.

A second processor: the GPU

  • CPU, the central processing unit: a few cores, each fast, any program
  • GPU, the graphics processing unit: thousands of small cores, the same instruction on many numbers
  • Its own memory. The T4 that Colab lends: 2,560 cores, 16 GB, 8.1 trillion operations a second at peak
  • Built for the pixels of a screen: one short computation, millions of times
  • A product of matrices: work of the same kind

The page CPU and GPU, parts 1 and 2: ikoutis.github.io/cs301-labs/unit-2/pages/cpu-and-gpu.html

Notes. Five minutes, with parts 1 and 2 of the page on the screen. The processor that has run every program of this course so far is the CPU: a few cores, each able to run any program, one instruction after another, very fast. A GPU was built for one kind of work: the colours of the pixels of a screen, many times a second; one short computation repeated for millions of pixels that do not depend on each other. So it has thousands of small cores that carry out the same instructions on different numbers at once, and a memory of its own. A product of matrices is work of the same kind: each entry of the result is a sum of products that depends on no other entry. That is why neural networks are computed on GPUs.

  • One operation, one device: X_g @ W_t.T fails. .cpu() copies back
  • The line of the scores: unchanged
Notes. PyTorch names the GPU cuda, after the system with which NVIDIA's GPUs are programmed. .to('cuda') copies the numbers of a tensor into the memory of the GPU and returns the copy; an operation needs all of its tensors on one device, and the processor of that device carries it out; .cpu() copies a result back. Measure the product on both processors

def time_product(size, device):
    """The average time, in seconds, of X @ W.T + b on the device, with n = m = K = size."""
    X = torch.rand(size, size, device=device)        # random float32 numbers, made on the device
    W = torch.rand(size, size, device=device)
    b = torch.rand(size, device=device)
    repeats = max(1, min(200, 8_000_000_000 // size ** 3))     # many repeats when the product is small
    finish(device)
    start = time.perf_counter()
    for _ in range(repeats):
        S = X @ W.T + b
    finish(device)
    return (time.perf_counter() - start) / repeats
  • n = m = K = size; random numbers made on the device; many repeats when small
  • torch.cuda.synchronize(): wait for the GPU before reading the clock
  • One small product first, not measured: the first use of a device is slow
Notes. Two details are particular to a GPU. PyTorch hands the work to the GPU and goes on at once, before the result is ready, so finish waits with torch.cuda.synchronize() before the clock is read; without it the clock would measure the handing over and not the work. And the first use of a device takes extra time, so one small product is run first and not measured.

Unit II Essentials

Meetings 10–14: matrix products, array operations, computational cost, hardware, linear systems and sparse matrices.

Data and neurons, as matrices The two ideas

  • Data: collect measurements in a table, then select features for X. Each row is a point; each column is a feature.
  • Neurons: each row of W contains one neuron's weights. W x + b computes their scores for one point.
  • We use matrix products to compare data and compute neuron scores, then examine their cost.

Part 1 of 7 · Meeting 14

Data × data

Use X XT to compare rows and XT X to compare columns.

Why we do this

  • To find similarities between observations and relationships between features.

Comparing observations and features Data × data

  • We can compare movies by who rated them, or people by the movies they rated.
  • Matrix products compute many of these comparisons together.

Learning targetExplain what a comparison measures, and how the representation of the data affects it.

Data × data: the two products Data × data

  • X: n observations as rows, m features as columns.
  • X XT is n × n: entry (i, j) is the dot product of observations i and j.
  • XT X is m × m: entry (a, b) is the dot product of features a and b.
  • A dot product multiplies corresponding entries and adds the results.
  • On the diagonal: an observation, or a feature, with itself.

Preprocessing changes the comparison Data × data

  • A raw dot product depends on the lengths of the vectors as well as on their directions.
  • Cosine similarity: for nonzero vectors, divide the dot product by the product of their lengths.
  • Correlation: centre and standardize each feature column; then C = ZT Z / n.
  • A missing rating is not a zero-star rating.

B records whether a rating exists. For C, standard deviations use divisor n and must be nonzero.

Part 2 of 7 · Meeting 11

Data × neurons

Compute a score for each data point and each neuron.

Why we do this

  • To apply a learned model to many observations at once.

Applying several rules to the same data Data × neurons

  • We want a score for each possible class or response.
  • Each neuron applies its own weights and bias to the same input features.

Learning targetExpress the computation of a layer as a matrix product, and interpret its output.

Data × neurons: one score for each point and neuron Data × neurons

  • One point, one neuron: s = wTx + b.
  • X: n × m, one point a row. W: K × m, one neuron a row.
  • S = X @ W.T + b is n × K: S[i, j] is the score of neuron j for point i.
  • Softmax gives probabilities per row; argmax returns the largest entry's index.
  • X and W both have m columns: one weight per input feature.

Part 3 of 7 · Meetings 10 and 11

Array expressions

Write a formula as operations on whole arrays: axes, broadcasting, and the two multiplications.

Why we do this

  • To translate mathematical formulas into correct, efficient code.

Translating a formula into array operations Array expressions

  • A wrong axis, or a wrong transpose, changes the computation.
  • The result's shape helps us check whether we computed a value per point or per feature.

Learning targetRead an array expression and explain what every result represents.

Axes, broadcasting and the two multiplications Array expressions

  • X[:, j] selects feature j; X[i, :] selects point i.
  • X.mean(axis=0): one mean per feature, shape (3,).
  • X.mean(axis=1, keepdims=True): one mean per point, shape (4, 1).
  • (X - X.mean(axis=0)) / X.std(axis=0) standardizes the feature columns.
  • * multiplies entry by entry; @ computes a matrix product.

Hardware

Explain how the processor, memory access and implementation affect running time.

Why we do this

  • To understand why code is slow and how to make it faster.

Explaining a measured running time Hardware

  • Programs with the same arithmetic count can take different amounts of time.
  • Python overhead, memory access and data transfers affect running time.

Learning targetExplain a timing result, and decide when a GPU is useful.

Where the time goes Hardware

  • Python overhead: vectorize, and the loop runs in compiled code.
  • Locality: nearby data, and reused data, can be served from the cache.
  • Throughput, bandwidth: arithmetic or data movement limits the rate.
  • GPU: speedups depend on workload size, setup and data-transfer costs.
  • Measure a completed computation; say whether the copies are included.

Part 6 of 7 · Meeting 13

Linear systems

Express linear relationships between unknown quantities as A p = b.

Why we do this

  • To find unknown quantities from known relationships between them.

Finding random-walk probabilities Linear systems

  • We want the probability of reaching the red endpoint first from each node.
  • The random walk gives one equation at each interior node.

Learning targetBuild a linear system, and judge what its numerical solution tells us.

Writing the random-walk equations as A p = b Linear systems

  • Each interior probability is the average of its neighbours' probabilities.
  • pu = (1 + pv) / 2 and pv = pu / 2: the known ends go to the right-hand side.
  • Elimination keeps the solution; back substitution finds the unknowns.
  • np.linalg.solve(A, b) gives pu = 2/3 and pv = 1/3.

Uniqueness, sensitivity and the residual Linear systems

  • A square system of full rank has one solution.
  • A rank-deficient square system has no solution or infinitely many.
  • A large condition number: possible sensitivity to small relative changes.
  • The residual r = b − A x̂ measures how closely x̂ satisfies the equations.
  • A small residual can occur even when the solution error is large.

Part 7 of 7 · Meeting 13

Sparse computation

Represent a matrix by its nonzero values and their locations.

Why we do this

  • To reduce memory and computation when most matrix entries are zero.

Storing a matrix with many zeros Sparse computation

  • Each node in this grid is connected to at most four neighbours.
  • The matrix needs entries for those neighbours and the diagonal.

Learning targetExplain when sparse storage and sparse algorithms reduce memory and work.

Sparse products and sparse solves Sparse computation

  • Sparse formats store the nonzero values and their positions.
  • A CSR product A @ v: O(nnz + N) work for N rows.
  • Elimination can create nonzeros: fill-in.
  • The order of elimination affects the fill-in, the storage and the arithmetic.
  • An iterative solver's total cost depends on the cost and number of updates.

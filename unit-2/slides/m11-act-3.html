O(nKm)

  • time ≈ (time of one pass) × n × K × m
  • O(nKm): how the count grows; the constant is dropped
  • n = m = K: the count is n³, so ×8 for each doubling
  • That is the factor of Act 2, from 2,048 to 4,096
  • A transpose and a reshape cost nothing: no number moves

The page What matrix operations cost: ikoutis.github.io/cs301-labs/unit-2/pages/matrix-costs.html

Notes. Computer science writes O(nKm), read 'of the order of n K m': the notation keeps how the number of operations grows with the sizes and drops the constant in front, the time of one pass. For a layer with n = m = K the count is n cubed, and doubling the size multiplies the time by 8: the factor the groups saw in Act 2 between the sizes 2,048 and 4,096. The page lists the count for every operation of the meeting.

Long arrays against short arrays: memory-bound

  • Two rows: the same additions, by the same code
  • Only the place of the numbers differs
  • Cache: a small, fast memory in the processor; the short arrays stay in it
  • Long arrays: fetched from the main memory, used once, sent back
  • Memory-bound: the memory sets the speed, not the arithmetic

The page CPU and GPU, parts 3 and 4

Notes. Five minutes on the two pairs of rows, with parts 3 and 4 of the page on the screen. The short arrays fit into the cache and stay there. The long arrays do not fit: each number has to be fetched from the main memory of the computer, is used in one addition, and the result is sent back; the processor spends most of its time waiting for numbers.

The product: compute-bound

  • In X @ W.T each entry of X meets the weights of every neuron
  • NumPy works on blocks that fit the cache; a number is used many times
  • Compute-bound: the time goes into arithmetic; every core helps
  • The GPU: thousands of small cores on the same product
  • Pays for large compute-bound work; not for small products
  • O( ) is the first estimate; the chart shows what it leaves out
Notes. NumPy's product is programmed to work on blocks of the two matrices that fit into the cache, and to use each number many times while it is there, so the processor spends its time on arithmetic; every core helps, and so do the instructions that handle several numbers at once. The GPU puts thousands of small cores on the same product, which pays for compute-bound work on large arrays and, as Act 2 measured, not for small ones. The O( ) notation leaves out how the program is run, where the numbers are, and which processor does the work.

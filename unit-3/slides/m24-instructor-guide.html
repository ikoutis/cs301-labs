80-minute interactive lecture

Run the meeting as an investigation of the question “Can we learn how to use our memory?” Preserve the live examples and the space for curiosity: phone-book roles, one unit of attention, descent in fog, choosing whose course advice is relevant, and the contrast between different sides of the room. Human-memory and déjà-vu questions are optional oral hooks for engagement; they need not be transferred into the student notes. Use a brief speculative question when it fits the room, then return to the quantity or operation the demonstration makes visible.

The mathematical arc is stored examples → computed attention → a positive temperature → a training objective → one-parameter optimization in PyTorch → evidence on separate queries → learned relevance → separate changes to memory and parameters → vector-valued convex combinations. Return to three questions at transitions: What is stored? What do we recompute for this query? What can the optimizer change? Before moving a control, ask students for a prediction; afterward, ask them to explain what actually changed.

Make the temperature-only versus joint-training comparison a deliberate diagnostic moment. With only theta updated, rho remains 0.5; students should explain that before phi is allowed to learn. Reset to the same starting state for the joint run, use the same data and update budget, then compare validation errors. Training changes parameters; evaluation supplies evidence about the resulting predictor. Finish with vector-valued outputs inside the convex hull of the stored values, carrying the one-unit attention idea into geometry. The lecture assumes no notebook, submission destination, grade, or deadline.

Experimental design

The stored memory, parameter-training queries, and validation queries are disjoint. Training updates use only the parameter-training targets. Validation reports predictive performance and never supplies a gradient. The test set is not used. The intentional copying example is labeled separately and uses memory items as queries to expose self-retrieval. All data are synthetic teaching examples, not bike-rental observations.

The one-dimensional experiment isolates temperature. The two-dimensional experiment first trains temperature with relevance fixed at one half, then restarts from the same initial parameters and trains both. Switching modes is a fresh comparison, not a continuation. Ask what the optimizer is allowed to change before each run. Normalized feature weights sum to one, avoiding redundancy between their common scale and temperature. A temperature chosen by a good validation search can match a trained temperature. Neither experiment establishes a universal advantage.

The closing vector demonstration directly adjusts nonnegative attention shares that sum to one; it explores the geometry of weighted outputs, not an additional training algorithm. Scalar values give an interval; vector values give a convex hull. Optional human-memory connections appear in the instructor prompts as invitations to wonder. They are not required mathematical conclusions or additions to the student notes.

Memory

1. Learning how to use memory

Open with the live question: “We have memories, but can we learn how to use them?” Give students a moment to connect it to their own experience: sometimes the issue is which past experience to bring to a new situation. Keep the invitation open and conversational; it is the motivating hook for the meeting.

Then make the question concrete. The earlier neighbor predictor retained examples; a fitted neural network retained learned parameters. Today the model will retain both. Point to the stored observations and the new query: the data supply possible answers, while a learned rule controls their influence. Build that answer first with one temperature, then with a learned feature weight. All numerical demonstrations use synthetic teaching data.

Plant three questions that will return throughout the lecture: “What is stored? What do we recompute for this query? What can the optimizer change?” Do not answer all three immediately. Let each demonstration supply part of the answer. The broader human-memory connection can remain a live question; the technical claim we will establish is about this explicitly defined prediction model.

4. Queries, keys, and values

Begin with the phone-book example from the live class. “What is this person's phone number?” is the query; the stored name is the key; the paired number is the value. Ask students to name the three roles before showing the regression notation. Exact lookup establishes the vocabulary. Then switch to measured numerical targets, where combining values makes sense; we are not averaging phone numbers.

Introduce these three names before using them in the attention computation. Point to the new input q and call it the query. In each stored pair (x_i, y_i), x_i is the key: compare it with q to judge relevance. The paired target y_i is the value: it supplies a number to combine into the prediction. Keep the link between each key and its own value visible. Ask which part is used for matching and which part contributes to the answer. Expected: compare inputs, combine targets. The new query's unknown target is never used to compute similarity.

These are roles in a computation. In this regression example, the keys and values are observed inputs and targets. Other attention models can produce keys and values as learned vectors; this example is not a claim that all attention uses stored training labels. Source: Dive into Deep Learning, Queries, Keys, and Values, https://en.d2l.ai/chapter_attention-mechanisms-and-transformers/queries-keys-values.html.

Attention

5. From a query to a prediction

Use one table for the complete attention calculation, keeping the query and temperature in place. Begin with q=2.4 and tau=1. Ask which stored example should have the largest share before computing it. Keep all four teaching points visible while stepping through the columns.

Compare inputs: identify the query, each stored input key, and its paired target value. The query is its known input, not a point (q, y_hat) in the input-output plot. Its unknown target cannot enter the distance. For vector inputs, squared Euclidean distance sums the squared coordinate differences.

Score relevance: farther keys receive more negative scores. A score closer to zero is larger. Explicitly narrate the intermediate arithmetic that students asked for in the live class: compute scores, exponentiate, add the exponentials, and divide by their total. Scores themselves can be negative and do not sum to one. The implementation subtracts the maximum score before exponentiating; this preserves the normalized result and improves numerical stability. Explain that shift only if students ask about the displayed or coded arithmetic.

Normalize shares: “Imagine that I have one unit of attention to distribute across the memory.” Follow one row from its positive exponential to its fraction of the total. Ask students to check that the shares are nonnegative and sum to one. This attention-budget image is the central intuition: increasing one share leaves less of the unit for the others. These are coefficients in a prediction, not probabilities that a stored observation is correct.

Combine values: multiply each stored target by its share and add. Trace one entire row through alpha_i*y_i. A large target receiving little attention can contribute less than a moderate target receiving more. Ask students to predict what changes when the query moves, then move it: distances, shares, contributions, and the prediction are recomputed; the stored values and temperature stay fixed. There has been no optimizer step.

Close with the first answer to the recurring questions: stored pairs are the memory; attention is computed for the query; training has not happened yet. The normalized weighted average lies between the smallest and largest stored scalar values. Source: Dive into Deep Learning, Attention Pooling and Nadaraya–Watson Regression, https://classic.d2l.ai/chapter_attention-mechanisms/nadaraya-watson.html.

Attention

6. What is stored, and what is computed?

Use the columns to make the first pause in the recurring distinction. What is stored? The paired keys and values, together with the current temperature setting. What is computed for this query? Distances, scores, normalized attention shares, and the weighted prediction. At this stage the temperature has been chosen by hand; no optimizer has changed it.

Ask a student to name one quantity that changes when only the query moves, and one that stays fixed. Then connect the calculation to the smooth prediction curve. With fixed finite memory and positive temperature, exponential weighting gives a smooth prediction as a function of the query. This is Gaussian kernel regression, also called a Nadaraya–Watson estimator; the name is optional vocabulary, not a new algorithm to memorize.

At finite temperature all mathematical attention shares are positive, although faraway contributions can be too small to display or can underflow in finite precision. The demonstration compares the query with all stored keys. The next question is whether the temperature used in this computation should be chosen by eye or learned from prediction errors.

Temperature

7. Temperature controls concentration

Before each preset, ask for a prediction in plain language: “Will the one unit of attention be shared broadly, or will most of it go to a few observations?” After the change, ask students to point to the visual evidence. Keep “what changed?” attached to a specific control rather than to a new slide title.

Introduce the larger synthetic regression dataset: 40 stored observations, a scalar input x, and noisy target values. The same memory and query remain in place throughout this comparison. Use the high, local, and low temperature presets, then the slider to compare nearby settings. The three visible teaching points distinguish broad averaging, averaging nearby examples, and strong concentration. Begin at tau=1, then use the presets as demonstrations rather than as recommended universal settings.

At high temperature (preset tau=100), move the query and observe broad attention and a comparatively flat prediction curve. State the limit precisely: as tau tends to infinity for a fixed finite memory, scores tend to zero, softmax tends to uniform weights, and the prediction tends to the mean of stored targets. A large finite value approximates that limit.

At the local-averaging preset (tau=0.07), inspect queries near a peak and a valley. Several relevant noisy observations can support a prediction without making all stored targets equally influential. Ask students to choose a nearby slider value and explain its effect before consulting validation. Visual appearance alone is not proof of predictive accuracy.

At low temperature (preset tau=0.001), move across nearby keys and watch the attention and curve respond. With a unique nearest input, the prediction approaches its target as tau tends to zero. If nearest inputs tie, this rule shares limiting attention among them. At every positive temperature the prediction is continuous, though it may change rapidly. Small temperature does not always overfit; individual target noise matters in this constructed experiment. Keep the memory fixed so temperature is the cause of each displayed change.

9. Concentration and ranking

Ask whether moving the temperature slider ever makes a more distant key outrank a closer key. For positive tau, dividing all negative squared distances by tau and applying softmax preserves their ordering. Temperature changes the ratio of their weights. Equal distances remain tied. This distinction will matter when an irrelevant feature causes the wrong observations to look close. It also prevents the phrase learned attention from suggesting that a single scalar can independently assign any desired weight to every example.

Learning

12. Choosing the temperature

Use one sentence before the notation: “Among positive temperatures, find one whose predictions make the average squared training error small.” Then identify the decision variable, fixed data, and loss on the slide. Have students say “difference, square, average” as you build the MSE; this ties the optimization problem to something they already understand.

State the optimization problem before the animation. Hold the memory M={(x_i,y_i)} and the m training-query pairs (q_j,t_j) fixed. For every candidate positive temperature tau, compute each attention prediction y_hat_tau(q_j), compare it with its observed training target t_j, square the residual, and average. The objective is L_train(tau) = (1/m) sum_j (y_hat_tau(q_j)-t_j)^2. We seek a positive tau that makes this loss small. The temperature is the decision variable; the observed inputs and targets are data. The memory's y_i values and the fitting queries' t_j targets have different roles, even though both are observed target values.

Use tau=exp(theta) to preserve positivity, then apply gradient updates to L_train(exp(theta)). Theta=0 gives tau=1; negative theta still gives a positive temperature. We do not need to derive the complete gradient on the slide. The supplied implementation computes it analytically and checks it against finite differences. A finite gradient run seeks a low-loss solution. It does not establish a global minimum, and the best value over positive tau can be approached at a boundary rather than attained at a finite temperature.

Validation observations are absent from this optimization objective. Their error will assess the resulting predictor and inform model choices. A final test remains separate. This makes the narrative distinction precise: learning changes a parameter using the training objective; evaluation asks how well the resulting procedure predicts other observations.

14. PyTorch: one trainable scalar

Present the code as a short tour of the same experiment, not a fresh algorithm. Ask students to find the answer to “What did we allow to change?” in the optimizer's parameter list. There is one item: theta. Contrast that with the memory tensors, which are used in the forward computation but are not optimized.

Bridge directly from the live temperature animation to its PyTorch implementation. The full downloadable script uses the exact same fixed synthetic observations as the lecture, loaded from results.json. Its tensors(rows) helper makes one-dimensional tensors of inputs and targets. All data tensors have requires_grad=False. Memory has 40 keys and 40 paired values; training has 80 query/target pairs; validation has another 160. The files are supplied together, so no dataset download is needed.

Point to torch.nn.Parameter: theta is one scalar leaf parameter. The optimizer receives [theta] explicitly, which is the complete list of learned quantities in this example. Parameter initialization at zero means exp(theta)=1. Memory values participate in predictions but they are not in the optimizer and are not adjusted. No neural-network layer or Module subclass is needed to optimize one differentiable scalar. The full script uses float64 on CPU for a close numerical comparison with the existing reference; this is a reproducibility detail, not a new learning concept. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.parameter.Parameter.html and https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html.

Learning

15. PyTorch: predict and measure error

Walk down the code in the same order as the mathematical definition. exp(theta) keeps tau positive and preserves the derivative connection to theta. q[:, None] has shape (80,1), while keys[None,:] has shape (1,40), so broadcasting produces an (80,40) matrix of squared distances. Each row contains the distances for one query. dim=1 in softmax therefore normalizes across stored keys, giving each query its own attention distribution. alpha @ values is an (80,40) matrix times a (40,) vector and returns 80 predictions.

The mean squared error is one scalar over the separate training targets. PyTorch records the chain from theta through exp, division, softmax, weighted sum, and loss so backward can compute its derivative. Do not call theta.item(), detach(), or torch.tensor(theta) inside predict: that would break the intended gradient path. Do not place this training forward pass inside no_grad. The fixed data need no gradients for theta to receive a gradient. Source: PyTorch Automatic Differentiation, https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html; torch.softmax, https://docs.pytorch.org/docs/stable/generated/torch.softmax.html.

Slide text

The attention formula becomes a few tensor operations, all connected to θ.

def predict(q):
    tau = theta.exp()
    d2 = (q[:, None] - keys[None, :]).square()
    alpha = torch.softmax(-d2 / tau, dim=1)
    return alpha @ values

pred = predict(q_train)
loss = (pred - t_train).square().mean()

Learning

16. PyTorch: backward, step, repeat

Use the walkthrough to connect the code to real output from pytorch-temperature.py, recorded in pytorch-results.json. These displayed checkpoints were executed using PyTorch on CPU with float64, not generated by the browser pretending to run Python. The prior training slide performs the corresponding updates live in JavaScript; this slide explains the actual PyTorch program.

First clear gradients: PyTorch accumulates gradients unless they are reset. Recompute a fresh loss at the current theta, then call backward to populate theta.grad. At the initial theta=0, the gradient is 0.14279783879110647 and the training MSE is 0.28187427780057106. backward alone does not change theta. optimizer.step applies theta_new=theta_old-0.2*theta.grad, giving theta=-0.028559567758221296 and tau=0.971844401829539 after one update. The script checks this gradient against a central finite difference.

The code uses full-batch gradient descent even though PyTorch names the optimizer SGD: each update uses all 80 training queries, with no momentum or weight decay. After the fixed budget of 500 updates, theta=-2.6829986421922136, tau=0.06835786573448518, training MSE=0.12917563875331126, and validation MSE=0.13959742532241623. These agree with the lecture reference to numerical precision.

Evaluation is a separate forward computation on q_valid with t_valid used only to measure its error. no_grad prevents a gradient graph from being recorded; it does not itself change theta or guarantee a fair split, which comes from the data construction. There is no backward or optimizer.step in the evaluation block. No dropout or batch normalization is present, so a Module.eval call is unnecessary here. Source: PyTorch Optimizing Model Parameters, https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html.

Finish the code tour with a quick prediction check: “If I run backward but never step, does the temperature change?” No: backward computes its derivative. “If I give the fitted program a new query, do I need backward?” No: forward prediction recomputes attention using the retained memory and current parameter.

Slide text

Autograd computes the derivative; SGD changes θ. Validation stays outside the update.

for step in range(500):
    optimizer.zero_grad()
    loss = (predict(q_train) - t_train).square().mean()
    loss.backward()
    optimizer.step()

with torch.no_grad():
    valid_mse = (predict(q_valid) - t_valid).square().mean()

Evaluation

18. Copying and prediction are different tests

Frame the transition with two short questions: “What changed during learning?” and “What would convince us that the learned rule predicts useful answers?” The first concerns the training procedure; the second concerns empirical evidence from evaluation. A lower training loss answers only the first part of the story.

Transition from Learning to Evaluation: learning asked how training errors choose a temperature; evaluation asks whether the resulting rule predicts other observations fairly. Empirical evidence means the results of these checks, not a different kind of parameter or a synonym for stored values.

This single demonstration keeps the temperature and memory visible while changing the evaluation rule. Deliberately use memory observations themselves as queries. Start at tau=0.001 with each query's own entry included, then lower the temperature further. With distinct inputs and a unique zero-distance match, the limiting prediction retrieves its own target. A tiny resubstitution error describes this copying task; it does not establish prediction for new observations. The main training experiment used separate query rows and avoided this setup.

At the same temperature, exclude each query's own entry and inspect the changed predictions and error. This is a leave-one-out prediction within training. The illustrated query must also exclude its own row when the control is active; the error readout averages this operation over all memory queries. Removing the same row does not automatically prevent leakage from duplicates, related observations, or future information. For forecasting, memory may contain only information available before prediction time.

Keep the separate validation score visible in both states. Excluding a memory query from its own prediction does not change the validation computation, which uses the full original memory and separate validation inputs. These are different evaluation sets and tasks; their numerical losses are not interchangeable by definition. No optimizer update occurs when toggling inclusion. This comparison motivates the next slide's explicit data roles.

Evaluation

21. Learning and tuning can choose the same value

Avoid overselling the single learned scalar. For this same memory and formula, a manually chosen or grid-searched temperature equal to the learned temperature produces identical predictions. Learning does not expand this scalar-temperature family. Its conceptual value is that the rule is differentiable and can be fitted together with other parameters. Which procedure works better depends on its objective, data, budget, and initialization. The next experiment adds a parameter that can actually change which keys look relevant, rather than merely changing concentration within a fixed ordering.

Use this as the bridge into the live surprise: “If temperature can only change concentration, what happens when our distance rule is paying attention to the wrong feature?” Let a student propose changing the distance before introducing the extra parameter. The next experiment makes the value of joint training visible.

Slide text

A carefully tuned fixed temperature can match a trained temperature. Training supplies another way to choose the parameter.

Evaluation

22. Reflection: a perfect training score

Allow about 90 seconds to write and 30 seconds to discuss. Keep the prompt visible without revealing answers. Expected answer: the model can retrieve known targets when their own keys are present. This demonstrates memorization or resubstitution performance, not generalization. Evaluate disjoint queries whose targets are unavailable to the memory, or exclude the query's own entry during an appropriate training-only leave-one-out calculation and still retain independent validation. A strong answer also notices duplicates or temporal leakage. Do not say memory itself is invalid; the problem is whether the evaluation resembles the intended new-query task.

Relevance

23. Feature weights change what looks close

Recall the course-choice example: when choosing a class, students hear reports from others, but not every detail about the reporter or their experience is equally useful. Which differences should matter when deciding whose experience is relevant? Invite one concrete suggestion, then point to the two coordinates in the controlled experiment.

The side-of-the-room example is useful here too: changing how sharply we focus on the current ordering differs from changing which group looks relevant in the first place. Point to opposite parts of the room as a quick spatial image, then return to the plotted keys. The example is about which features define closeness, not a claim that a particular group is inherently more trustworthy.

Announce the separate two-dimensional synthetic experiment before using this comparison. Both coordinates have the same numerical range, so the issue is relevance rather than incompatible units. The target generator depends on x1 plus noise; x2 is unrelated. Begin with equal feature weights (phi=0 gives rho=0.5) and ask which examples ought to matter for the displayed query. Similarity in x2 can otherwise favor an observation whose x1 is less relevant.

Use the feature-weight control or preset to emphasize x1 while holding temperature and the query fixed. Inspect the distance contour and the changed attention. A high relevance setting such as phi=4 gives rho=sigmoid(phi) near one; read the actual displayed value. The distance now emphasizes differences in x1 and discounts differences in x2, which can change the ordering of the stored examples. The three persistent points distinguish the distractor, changed relevance, and temperature's separate role.

Return to equal feature weights and vary temperature to contrast the effects. For a fixed metric, temperature can concentrate or spread attention but cannot repair its ordering. Move the query only after comparing settings at one fixed query. Do not suggest that the first coordinate should always receive more weight: the constructed generator gives that knowledge here, whereas a real task needs training and independent evaluation. Relevance

24. Learning relevance and concentration

Introduce only two learned scalars: theta determines a positive temperature and phi determines rho in (0,1). The feature weights sum to one, separating relative feature importance from the overall distance scale. Without a scale convention, multiplying all feature-distance weights and temperature by the same positive factor leaves attention unchanged. The normalized form removes that simple redundancy. It is still a restricted diagonal metric, not an arbitrary learned representation or a guarantee of finding every useful relationship. The gradient flows through the weighted distance, softmax, weighted targets, and prediction loss.

Before training, ask students to name the two jobs. Theta controls concentration through tau; phi changes the relative feature weight through rho and can therefore change the ordering of the keys. Ask: “If phi is absent from the update, should rho move?” This prepares the diagnostic moment on the next slide.

Relevance

25. First train τ; then train τ and relevance

Stage the temperature-only versus joint-training moment deliberately. Begin with the same initial parameters, fixed memory, training queries, and validation rows for both runs. State the update budget so the comparison is concrete. Ask: “What did we allow to change?” For the first run, the answer is theta only. Phi is fixed at zero, so rho must remain 0.5.

Run temperature-only training and pause on the unchanged feature weight. Invite students to explain why it stayed at 0.5 before changing modes. Treat it as a successful diagnosis: the model cannot learn a parameter that the training procedure does not update. Temperature can improve concentration under the equal-feature metric, but it cannot change that metric's ranking. With the supplied 800-update run, validation MSE is about 0.2157.

Now ask: “What additional thing must we allow to change if we want the model to learn which feature matters?” Select joint training of theta and phi; changing the Learn mode automatically restarts from the same initial parameters. Use the 800-update control for both runs when comparing the supplied endpoints. Make clear that this is a second fit from the shared starting point, not a continuation of the first run. Watch rho, the distance contours, and attention change together. Keep the same query while comparing the geometry. Return to the manual relevance demonstration if students want to explore other queries.

At the supplied 800-update checkpoint, rho is about 0.9749 and validation MSE is about 0.0863. Read the actual display, not a memorized score, if the controls or budget differ. Ask students to describe the two effects: learning concentration, and learning which keys look close. The side-of-the-room analogy can return in one sentence: we can now change whom we attend to, as well as how concentrated that attention is.

End by separating learning from evidence. Training-query errors updated the two parameters; the separate validation comparison is evidence that the richer rule helped on this synthetic task. The target generator depends on x1, so the learned direction is interpretable here. It is not a guarantee that every extra parameter improves validation or that rho must reach one. This is the payoff: stored observations supply the values, and learned parameters improve how the model uses them.

Relevance

26. A weighted average has limits

Return to the weights summing to one. No combination of positive normalized weights can produce a scalar prediction beyond the range of the stored targets. Learned temperature and feature weights do not remove that limitation. The model can also behave poorly in sparse regions even if its output remains within range. This is a useful boundary on the claim that memory plus learned weights is powerful: it improves a concrete rule but does not provide arbitrary extrapolation or cure every data problem.

If using the live earthquake example, keep its mathematical point precise: a normalized weighted average of recorded magnitudes cannot exceed the largest magnitude supplied as a value. That describes this predictor's output restriction. The engaging question is “What would the model need to change to produce an answer outside what its stored values can combine into?” Leave that question open here; the final vector-valued picture generalizes the restriction we can prove.

Memory and parameters

27. Change memory while parameters stay fixed

Pay off the question planted earlier: “Can a new memory change attention even if no parameter is retrained?” Return to the one-dimensional experiment and its learned temperature. Use three small interventions and ask students to predict the result before each one. Keep the distinctions visible throughout.

First, move the query with the memory and tau fixed. Distances, attention, and the prediction are recomputed for the new input. A query is not automatically stored. No loss or optimizer update is needed.

Second, return to a fixed query and add the observation at x=2.4. The new key adds an exponential term to the softmax denominator, so the existing shares are redistributed. The memory changed; tau did not. Removing and adding the observation again makes the effect clear. The altered predictor is immediately computable with the current parameters. Retraining is an optional later choice, not a prerequisite for using a new memory.

Third, leave the query, added key, and temperature fixed, and change only the added value. Ask students what will happen to its attention share before moving the value control. The attention remains the same, because it depends on the query, keys, and parameters. The prediction changes by alpha_i times the change in that value. Read two settings to make the arithmetic concrete. This is a controlled value edit or corrected observation, not a method for modifying labels until a score improves.

Close by naming the fourth operation that the controls did not perform: retraining would use an objective and optimizer steps to change parameters. New attention does not itself imply learning. A new observation can help or harm, and the old validation score does not certify the changed memory; the earlier comparison referred to the fixed original bank.

Memory and parameters

28. Identify the source of a changed prediction

Read the four-row action table as a final check of the three recurring questions. A fitted model contains both kinds of retained information. Stored memory consists of keys and paired values. Persistent parameters specify the rule for using that memory: theta, and phi in the two-feature model. A new query triggers fresh distance, attention, and prediction computations. An optimizer step uses training errors to update the parameters.

Have students explain the table rows aloud: a new query, an added observation, a corrected stored value, and another training step. Do not let “the model changed” serve as the entire answer; ask what changed and what stayed fixed. Attention can change under the first two operations without a parameter update. Editing a value alone leaves attention unchanged. Retraining changes the parameter rule and usually changes attention as a consequence.

If useful, connect this to ordinary kNN and the earlier neural network. A memory can grow with the stored observations even when only one or two scalars are learned. The term non-parametric does not forbid every learned parameter. The central point for today is the concrete retained state: memory together with a learned rule for consulting it.

A different prediction can come from a new query, changed memory, or changed parameters.

Memory and parameters

29. Memory, learning, and prediction

Invite a justification before each answer. Preserve the distinction between learned parameters and computed attention weights. The main demonstration uses disjoint training memory and fitting queries, with separate validation. A query's new attention distribution requires a forward computation but no retraining. Temperature preserves ranking for a fixed distance rule, while feature weights can change that ranking. The range claim follows from the normalized positive weights, not from the particular synthetic data. If time is short, prioritize the first, third, and fourth questions because they test the meeting's central memory-and-parameters idea.

Use answers to decide whether to revisit a control briefly. In particular, ask students to support “no retraining” by naming what a forward pass recomputes, and to support the output-range claim by naming nonnegative weights whose sum is one. That last answer sets up the final extension: “What if the stored values themselves are vectors?”

  2. No. Positive temperature changes concentration while preserving the ranking.
  3. Separate training queries and their targets, using the fixed training memory.
  4. The distances and therefore which keys receive the most attention.

Memory and parameters

30. Vector values stay inside their convex hull

Finish with the spontaneous extension from the live class: “What if the stored targets are not numbers but vectors?” Keep the attention coefficients scalar. For each stored vector value v_i, multiply every coordinate by the same alpha_i, then sum the vectors. The prediction is still y_hat = sum_i alpha_i v_i, with alpha_i nonnegative and sum_i alpha_i = 1.

Ask students to predict where the output can go before moving any controls. With two vector values it stays on their line segment; with three non-collinear values it stays inside their triangle; with more values it stays inside their convex hull. Trace how the point moves toward a value that receives more attention. Use “one unit of attention” again to connect the final geometry to the earlier scalar computation.

If the final demonstration directly lets students choose nonnegative shares, explain that it explores the geometry of any convex combination. It does not assert that the trained scalar-temperature model can realize every possible set of shares. A finite positive softmax assigns positive mathematical shares to every finite score, so an exact extreme vertex generally requires a limiting or hard-selection case. Direct share controls can include such endpoint cases.

Name the mathematical object after students have described the picture: a convex combination lies in the convex hull of the stored value vectors. This concerns value space; a two-dimensional input scatter plot was a picture of keys, and is a different space. Learned temperature and relevance weights can move the prediction by changing its shares, but they do not remove this convex-hull restriction for this averaging operation. Other layers in a larger model can transform its result.

End on that picture rather than another verbal recap: the model can retain examples, learn how to combine them, and return a scalar or a vector. The geometry makes both its power and its boundary visible.

Slide text

The same attention shares can combine whole vectors. What changes is the shape of the possible outputs.

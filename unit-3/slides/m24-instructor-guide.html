Learning how to use memory

80-minute interactive lecture

Open slidesTeaching routeSources

This 30-slide, 80-minute lecture connects stored examples with learned parameters. Query, key, and value are introduced before one interactive walkthrough computes attention. A single temperature comparison explores broad, local, and concentrated influence with visible teaching points. An explicit loss-minimization objective leads to the training demonstration; three short PyTorch slides translate the same one-parameter model into tensors, a forward pass, and an optimization loop. Evaluation contrasts copying, leave-one-out prediction, and separate validation in one view. A two-feature comparison introduces learned relevance, and a final memory-edit demonstration separates fixed parameters from changing stored observations. Repeated views share controls and persistent bullets; the loss landscape, optimization formulas, training runs, code, and reflections remain separate because they serve different purposes. Two prompt-only reflections and a closing review give students time to explain the distinctions. The lecture assumes no notebook, submission destination, grade, or deadline.

Experimental design

The stored memory, parameter-training queries, and validation queries are disjoint. Training updates use only the parameter-training targets. Validation reports predictive performance and never supplies a gradient. The test set is not used. The intentional copying example is labeled separately and uses memory items as queries to expose self-retrieval. All data are synthetic teaching examples, not bike-rental observations.

The one-dimensional experiment isolates temperature. The two-dimensional experiment adds a distractor feature on the same numerical scale and learns normalized feature relevance. The normalized feature weights sum to one, avoiding redundancy between their common scale and temperature. A temperature chosen by a good validation search can match a trained temperature. Neither experiment establishes a universal advantage. Convex combinations of untransformed stored targets remain within the stored target range.

Attention

4. Queries, keys, and values

Introduce these three names before using them in the attention computation. Point to the new input q and call it the query. In each stored pair (x_i, y_i), x_i is the key: compare it with q to judge relevance. The paired target y_i is the value: it supplies a number to combine into the prediction. Keep the link between each key and its own value visible. Ask which part is used for matching and which part contributes to the answer. Expected: compare inputs, combine targets. The new query's unknown target is never used to compute similarity.

These are roles in a computation. In this regression example, the keys and values are observed inputs and targets. Other attention models can produce keys and values as learned vectors; this example is not a claim that all attention uses stored training labels. Source: Dive into Deep Learning, Queries, Keys, and Values, https://en.d2l.ai/chapter_attention-mechanisms-and-transformers/queries-keys-values.html.

Slide text

Compare a new input with stored inputs. Use their associated targets to form a prediction.

Attention

5. From a query to a prediction

Use one table for the complete attention calculation. Keep all four teaching points visible while stepping through distance, score, normalized weight, and weighted value. The active point and columns identify the current step; the query and temperature stay in the same view. Start with q=2.4 and tau=1, and hold temperature fixed during the first pass. Before revealing each next step, ask students to predict which stored example should contribute most.

Compare inputs: identify the query, each stored input key, and its paired target value. Squared Euclidean distance uses input features only. The new query's unknown target never enters the similarity calculation. For vector inputs, squared distance is the sum of squared coordinate differences.

Score relevance: a large squared distance becomes a more negative score. Scores closer to zero are larger. Scores can be negative and do not add to one. Exponentiating produces positive quantities. The implementation subtracts the largest score before exponentiating; this preserves normalized weights while improving numerical stability. That implementation detail belongs in the guide, not the main narration.

Normalize shares: divide each exponential by the sum of all exponentials. This is softmax. Ask students to check that the weights are nonnegative and sum to one. The shared denominator couples them: changing one score changes other normalized shares too. They describe how this prediction combines values; they are not probabilities that an observation is correct, and they are not persistent learned parameters.

Combine values: follow one row from distance through weight to alpha_i*y_i, then add the contributions to obtain the prediction. A large target with little attention can contribute less than a moderate target with substantial attention. Move the query and trace one row again; its weight and contribution change, while its stored target stays fixed. The convex combination stays between the smallest and largest stored values. Source: Dive into Deep Learning, Attention Pooling and Nadaraya–Watson Regression, https://classic.d2l.ai/chapter_attention-mechanisms/nadaraya-watson.html.

6. A smooth memory predictor

Summarize the actual computation without replaying every arithmetic step. With a fixed finite memory and a positive temperature, the exponential weighting gives a smooth prediction as a function of the query. This model is Gaussian kernel regression, also called a Nadaraya–Watson estimator. The name is optional vocabulary, not a new algorithm to memorize. At finite temperature all mathematical weights are positive, although faraway contributions may be too small to display or may underflow in finite precision. Computing attention over the full memory requires comparing all stored keys in this demonstration.

7. Temperature controls concentration

Introduce the larger synthetic regression dataset: 40 stored observations, a scalar input x, and noisy target values. The same memory and query remain in place throughout this comparison. Use the high, local, and low temperature presets, then the slider to compare nearby settings. The three visible teaching points distinguish broad averaging, averaging nearby examples, and strong concentration. Begin at tau=1, then use the presets as demonstrations rather than as recommended universal settings.

At high temperature (preset tau=100), move the query and observe broad attention and a comparatively flat prediction curve. State the limit precisely: as tau tends to infinity for a fixed finite memory, scores tend to zero, softmax tends to uniform weights, and the prediction tends to the mean of stored targets. A large finite value approximates that limit.

At the local-averaging preset (tau=0.07), inspect queries near a peak and a valley. Several relevant noisy observations can support a prediction without making all stored targets equally influential. Ask students to choose a nearby slider value and explain its effect before consulting validation. Visual appearance alone is not proof of predictive accuracy.

At low temperature (preset tau=0.001), move across nearby keys and watch the attention and curve respond. With a unique nearest input, the prediction approaches its target as tau tends to zero. If nearest inputs tie, this rule shares limiting attention among them. At every positive temperature the prediction is continuous, though it may change rapidly. Small temperature does not always overfit; individual target noise matters in this constructed experiment. Keep the memory fixed so temperature is the cause of each displayed change.

9. Concentration and ranking

Ask whether moving the temperature slider ever makes a more distant key outrank a closer key. For positive tau, dividing all negative squared distances by tau and applying softmax preserves their ordering. Temperature changes the ratio of their weights. Equal distances remain tied. This distinction will matter when an irrelevant feature causes the wrong observations to look close. It also prevents the phrase learned attention from suggesting that a single scalar can independently assign any desired weight to every example.

Slide text

Learning

12. Choosing the temperature

State the optimization problem before the animation. Hold the memory M={(x_i,y_i)} and the m training-query pairs (q_j,t_j) fixed. For every candidate positive temperature tau, compute each attention prediction y_hat_tau(q_j), compare it with its observed training target t_j, square the residual, and average. The objective is L_train(tau) = (1/m) sum_j (y_hat_tau(q_j)-t_j)^2. We seek a positive tau that makes this loss small. The temperature is the decision variable; the observed inputs and targets are data. The memory's y_i values and the fitting queries' t_j targets have different roles, even though both are observed target values.

Use tau=exp(theta) to preserve positivity, then apply gradient updates to L_train(exp(theta)). Theta=0 gives tau=1; negative theta still gives a positive temperature. We do not need to derive the complete gradient on the slide. The supplied implementation computes it analytically and checks it against finite differences. A finite gradient run seeks a low-loss solution. It does not establish a global minimum, and the best value over positive tau can be approached at a boundary rather than attained at a finite temperature.

Validation observations are absent from this optimization objective. Their error will assess the resulting predictor and inform model choices. A final test remains separate. This makes the narrative distinction precise: learning changes a parameter using the training objective; evaluation asks how well the resulting procedure predicts other observations.

Slide text

14. PyTorch: one trainable scalar

Bridge directly from the live temperature animation to its PyTorch implementation. The full downloadable script uses the exact same fixed synthetic observations as the lecture, loaded from results.json. Its tensors(rows) helper makes one-dimensional tensors of inputs and targets. All data tensors have requires_grad=False. Memory has 40 keys and 40 paired values; training has 80 query/target pairs; validation has another 160. The files are supplied together, so no dataset download is needed.

Point to torch.nn.Parameter: theta is one scalar leaf parameter. The optimizer receives [theta] explicitly, which is the complete list of learned quantities in this example. Parameter initialization at zero means exp(theta)=1. Memory values participate in predictions but they are not in the optimizer and are not adjusted. No neural-network layer or Module subclass is needed to optimize one differentiable scalar. The full script uses float64 on CPU for a close numerical comparison with the existing reference; this is a reproducibility detail, not a new learning concept. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.parameter.Parameter.html and https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html.

Learning

15. PyTorch: predict and measure error

Walk down the code in the same order as the mathematical definition. exp(theta) keeps tau positive and preserves the derivative connection to theta. q[:, None] has shape (80,1), while keys[None,:] has shape (1,40), so broadcasting produces an (80,40) matrix of squared distances. Each row contains the distances for one query. dim=1 in softmax therefore normalizes across stored keys, giving each query its own attention distribution. alpha @ values is an (80,40) matrix times a (40,) vector and returns 80 predictions.

The mean squared error is one scalar over the separate training targets. PyTorch records the chain from theta through exp, division, softmax, weighted sum, and loss so backward can compute its derivative. Do not call theta.item(), detach(), or torch.tensor(theta) inside predict: that would break the intended gradient path. Do not place this training forward pass inside no_grad. The fixed data need no gradients for theta to receive a gradient. Source: PyTorch Automatic Differentiation, https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html; torch.softmax, https://docs.pytorch.org/docs/stable/generated/torch.softmax.html.

Slide text

The attention formula becomes a few tensor operations, all connected to θ.

def predict(q):
    tau = theta.exp()
    d2 = (q[:, None] - keys[None, :]).square()
    alpha = torch.softmax(-d2 / tau, dim=1)
    return alpha @ values

pred = predict(q_train)
loss = (pred - t_train).square().mean()

Learning

16. PyTorch: backward, step, repeat

Use the walkthrough to connect the code to real output from pytorch-temperature.py, recorded in pytorch-results.json. These displayed checkpoints were executed using PyTorch on CPU with float64, not generated by the browser pretending to run Python. The prior training slide performs the corresponding updates live in JavaScript; this slide explains the actual PyTorch program.

First clear gradients: PyTorch accumulates gradients unless they are reset. Recompute a fresh loss at the current theta, then call backward to populate theta.grad. At the initial theta=0, the gradient is 0.14279783879110647 and the training MSE is 0.28187427780057106. backward alone does not change theta. optimizer.step applies theta_new=theta_old-0.2*theta.grad, giving theta=-0.028559567758221296 and tau=0.971844401829539 after one update. The script checks this gradient against a central finite difference.

The code uses full-batch gradient descent even though PyTorch names the optimizer SGD: each update uses all 80 training queries, with no momentum or weight decay. After the fixed budget of 500 updates, theta=-2.6829986421922136, tau=0.06835786573448518, training MSE=0.12917563875331126, and validation MSE=0.13959742532241623. These agree with the lecture reference to numerical precision.

Evaluation is a separate forward computation on q_valid with t_valid used only to measure its error. no_grad prevents a gradient graph from being recorded; it does not itself change theta or guarantee a fair split, which comes from the data construction. There is no backward or optimizer.step in the evaluation block. No dropout or batch normalization is present, so a Module.eval call is unnecessary here. Source: PyTorch Optimizing Model Parameters, https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html.

Slide text

Autograd computes the derivative; SGD changes θ. Validation stays outside the update.

for step in range(500):
    optimizer.zero_grad()
    loss = (predict(q_train) - t_train).square().mean()
    loss.backward()
    optimizer.step()

with torch.no_grad():
    valid_mse = (predict(q_valid) - t_valid).square().mean()

17. Learned parameters and attention weights

This distinction deserves a direct check. Ask whether moving the query after training is another training step. It is not: the fixed parameters and new input produce new attention weights as part of inference. The word weights can mean different quantities. Alpha_i(q) are normalized coefficients for this prediction. Theta is the persistent learned parameter controlling how those coefficients are computed. The stored target values are retained observations, not independently optimized coefficients in this model. A model can therefore combine a growing memory with a small fixed number of learned parameters.

Slide text

Learning changes a shared parameter. Prediction computes a new attention distribution for each query.

Evaluation

18. Copying and prediction are different tests

Transition from Learning to Evaluation: learning asked how training errors choose a temperature; evaluation asks whether the resulting rule predicts other observations fairly. Empirical evidence means the results of these checks, not a different kind of parameter or a synonym for stored values.

This single demonstration keeps the temperature and memory visible while changing the evaluation rule. Deliberately use memory observations themselves as queries. Start at tau=0.001 with each query's own entry included, then lower the temperature further. With distinct inputs and a unique zero-distance match, the limiting prediction retrieves its own target. A tiny resubstitution error describes this copying task; it does not establish prediction for new observations. The main training experiment used separate query rows and avoided this setup.

At the same temperature, exclude each query's own entry and inspect the changed predictions and error. This is a leave-one-out prediction within training. The illustrated query must also exclude its own row when the control is active; the error readout averages this operation over all memory queries. Removing the same row does not automatically prevent leakage from duplicates, related observations, or future information. For forecasting, memory may contain only information available before prediction time.

Keep the separate validation score visible in both states. Excluding a memory query from its own prediction does not change the validation computation, which uses the full original memory and separate validation inputs. These are different evaluation sets and tasks; their numerical losses are not interchangeable by definition. No optimizer update occurs when toggling inclusion. This comparison motivates the next slide's explicit data roles.

24. Learning relevance and concentration

Introduce only two learned scalars: theta determines a positive temperature and phi determines rho in (0,1). The feature weights sum to one, separating relative feature importance from the overall distance scale. Without a scale convention, multiplying all feature-distance weights and temperature by the same positive factor leaves attention unchanged. The normalized form removes that simple redundancy. It is still a restricted diagonal metric, not an arbitrary learned representation or a guarantee of finding every useful relationship. The gradient flows through the weighted distance, softmax, weighted targets, and prediction loss.

Relevance

26. A weighted average has limits

Return to the weights summing to one. No combination of positive normalized weights can produce a scalar prediction beyond the range of the stored targets. Learned temperature and feature weights do not remove that limitation. The model can also behave poorly in sparse regions even if its output remains within range. This is a useful boundary on the claim that memory plus learned weights is powerful: it improves a concrete rule but does not provide arbitrary extrapolation or cure every data problem.
